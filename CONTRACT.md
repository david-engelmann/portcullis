# Contract

Portcullis asks whether every tool call an agent proposes can be judged at the call itself, against the rules that govern the call, before the call reaches the machine it would run on. This file is the stub contract for the setup slice. It states the setup obligations only, and each obligation is stated so it can fail.

Obligation S1 covers seed integrity. The seed files README.md and LICENSE and .gitignore are present from the first commit, and every later change lands through a pull request rather than a direct push to main. This is covered by inspection of the repository history and by the status section of the README.

Obligation S2 covers the local gate. The test suite runs with python and pytest alone and running it needs no network access and no paid service, and the continuous integration workflow runs the same commands as the local gate. This is covered by the tests in the tests folder and by the workflow in the .github folder.

Obligation S3 covers honest status. The README status section records the seed state and the contract state truthfully and it reports closed perfection rounds as 0 of 100 until a full cycle of work and audit and review and red team and approval has closed. This is covered by inspection of the README against this contract and against the repository history.

Obligation S4 covers synthetic content only. Every fixture and every example in this repository is synthetic and written for this repo, and no file carries a real trace or a real transcript or a real name or any private operational detail. This is covered by inspection of the repository contents before any push.

Obligation S5 covers the canonical agents file. The part of AGENTS.md above the marked line is identical to the canonical template for the program, and only the repo annex below the marked line differs for portcullis. This is covered by tests in the tests folder that pin the SHA-256 digest of the part above the marked line and check the marked line and the annex.

The full contract for portcullis is the first build act of this repo and it lands with the first slice. This stub is not the full contract, and no feature claim for portcullis rests on this stub.

## The full contract, Round 1 slice 1

The stub above stands unedited as the record of the setup state. What follows is the full contract the stub promised, landed as the first build act of this repo in Round 1 slice 1. Slice 1 builds the decision engine only. It takes one structured call record and one policy and returns one decision record, and it appends that decision to an audit log. The decision model slice that ROADMAP.md designs stands behind this same decision record shape when it lands in a later round, and slice 1 adds no model calls and reserves no model fields.

### Probe preamble

The obligations below rest on behaviour probed on this machine under Python 3.12.3 rather than on habit.

Eight processes each appending 25 JSON lines to one file, taking an exclusive flock around each line and flushing before releasing it, produced exactly 200 lines and every line was whole and parseable. Appends under one exclusive flock per line do not interleave on this machine.

Plain json.loads accepts a duplicated key and keeps the last value, at the top level and nested inside an object. An object_pairs_hook that refuses a repeated key detects the duplicate at every level. Plain json.loads accepts the non standard constants NaN and Infinity, and a parse_constant hook that raises refuses them. Data trailing a complete document raises a decode error. The strict readers in this slice are built from those three hooks and checks.

The glob matcher fnmatch.fnmatchcase from the standard library is case sensitive and its star crosses path separators, so the text a/b/c matches the pattern a/* and the text a/b matches the pattern star alone. The single character pattern ? matches exactly one character and a bracket pattern such as [!a] matches one character that is not a. The companion function fnmatch.fnmatch folds case under the platform normcase rule, so this slice matches with fnmatchcase and gets the same answer on every platform.

posixpath.normpath resolves dot segments lexically and touches no filesystem. It reads a/./b as a/b, a/../b as b, /../x as /x, a//b as a/b, ../a unchanged as ../a, a/../../b as ../b, a/ as a, and the empty string as a single dot.

The SHA-256 digest of the three bytes abc is ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad, the example value in FIPS 180-4, so the hashlib digests this slice records are the standard ones.

urllib.parse.urlparse lowercases the hostname it reports, so a URL naming EXAMPLE.com reports the host example.com. It reports an explicit port when the URL carries one and reports no port when the URL carries none, and it exposes any userinfo a URL carries as separate fields.

### Obligation PC-1 covers the call record

A call is one JSON document whose format field names portcullis-call/1 and whose kind field names one of shell and file and network. A shell call carries an argv array of one or more strings and may carry a cwd string. A file call carries an operation naming one of read and write and delete and move and list, a path string that is not empty, and a second path under the name path2 exactly when the operation is move. A network call carries a method string that is not empty and then either a host string that is not empty and a port or a url string. The port of a network call is an integer from 1 to 65535. A boolean is never an integer for any numeric field in this contract. When a network call carries a url, the host is the hostname the URL reports folded to lowercase and the port is the port the URL carries or the default port of the http or https scheme, and a URL that carries userinfo or leaves the port undetermined makes the call malformed. Reading a call is strict. A duplicated key at any level, a field the kind does not carry, a missing field the kind requires, and a value of the wrong type each make the parsed call fail schema validation. A document that does not parse as JSON at all is a caller error and no decision is made or recorded for it. A parsed document that fails schema validation is decided as a deny with the source named malformed. Bad input to the tool is the caller's bug, and a bad call from the agent is what the gate exists to refuse, and the two are never reported as one another. This is covered by tests that feed each malformed shape and each caller error shape and check the decision or the exit that comes back.

### Obligation PC-2 covers the policy record and its loading

A policy is one JSON document whose format field names portcullis-policy/1, whose default field names allow or deny, and whose rules field holds an ordered list of rules. The order of the rules is an evaluation input and the declared default is deny unless the policy declares allow. Each rule carries an id string that is not empty and that no other rule in the policy repeats, a kind, an action naming one of allow and deny and rewrite, a reason string that is not empty, and a match object holding at least one condition. A condition is a matcher, and a matcher holds exactly one of an exact string, a prefix string, or a glob string, except the port matcher, which holds one exact integer. A shell match may condition on argv0, which tests the first argv token exactly as given, and on argument positions of 1 or more, and an argument condition fails when the argv holds no token at that position. A file match may condition on the operation and on the path. A network match may condition on the method, tested case sensitively as given, on the host, tested with both sides folded to lowercase, and on the port. A rewrite rule carries a substitute object naming replacement values for fields of its kind, and no other rule carries one. Substitute values pass the same field validation as call fields of that kind. Policy reading is strict in the same way as call reading, and validation of every rule happens at load. A policy with any invalid part does not load at all, and no rule from an unloadable policy is ever applied. This is covered by tests that break one part of a policy at a time and check that loading refuses the whole policy each time.

### Obligation PC-3 covers the evaluation order

A decision is reached in four steps and in no other order. First, schema validation, and a call that fails it is denied with the source named malformed and no rule is consulted. Second, the deny rules of the policy in their policy order, and the first deny rule that matches the call denies it with that rule named as the source. Third, the allow and rewrite rules in their policy order, and the first that matches decides, allowing the call as proposed or rewriting it under that rule's substitute. Fourth, the declared default, and a call no rule matches takes the default with the source naming the default itself. A deny rule beats an allow rule and a rewrite rule whenever more than one matches, wherever each stands in the list, and a rewrite never rescues a call a deny rule has caught. A rule matches only a call of its own kind. Schema validation needs no policy, so a malformed call is denied as malformed even when the policy cannot be loaded. This is covered by tests that pin each step against the steps around it, including a call that matches both a deny and an allow rule, a call that matches both a deny and a rewrite rule, and two allow rules whose order is swapped to show the first match is the one that fires.

### Obligation PC-4 covers the decision record

A decision is one JSON document whose format field names portcullis-decision/1 and which carries the instant it was given under at, the digest of the call under call_digest, the outcome under decision as one of allow and deny and rewrite, the source under source, the reason under reason, the interpreter flag under interpreter, and the rewritten call under rewritten_call. The source names the rule id when a rule fired and otherwise names one of malformed and policy error and default, and a policy error source also states the detail of the load failure. The reason is the reason of the rule that fired and is null when no rule fired. The digest is the SHA-256 of the canonical form of the parsed call document, where canonical form means keys sorted, no spaces, and the text encoded as UTF-8 without ASCII escaping, written as the word sha256 followed by a colon and the hex digest. The rewritten call stands only on a rewrite decision and is the complete call document with the substitute applied and every other field carried intact, and it is never evaluated again. A rewrite whose result would fail the call validation of obligation PC-1 is not delivered as a rewrite, and the call is denied with that rule named as the source, because the gate must not hand a harness a call its own schema refuses. A rewrite of a network call given by url emits the rewritten call in the explicit method and host and port form. This is covered by tests that check each field of the decision for each source the gate can produce.

### Obligation PC-5 covers the interpreter marker

A decision on a shell call flags whether the call runs a shell interpreter, because the gate matches such a call as the interpreter call and treats its command string as one opaque argument, and an operator who allows an interpreter is allowing everything that interpreter can run. The marker is the interpreter field of the decision record. It is true exactly when the call passed schema validation, its kind is shell, and the basename of its first argv token names one of sh and bash and dash and ash and zsh and ksh and csh and tcsh and fish. It is false in every other decision, including every malformed one. When a rewrite delivers an interpreter call, the marker is true when either the proposed call or the delivered rewritten call is an interpreter call, even when the proposed call was not one. This is covered by tests that drive interpreter calls under several path shapes and non interpreter calls of every kind.

### Obligation PC-6 covers path matching

A file rule's path matcher is tested against the path exactly as the call gives it and against the lexical normalization of that path under posixpath.normpath, and a match on either form fires the rule. Matching resolves no symlink and stats no target, because the gate decides before the call happens and the filesystem can change between the decision and the call. The second path of a move call is carried in the call and may be replaced by a substitute, and it is not matched in slice 1. This is covered by tests in which one rule fires on the given form of a path and another fires only on its normalized form.

### Obligation PC-7 covers the audit log

Every decision the check command delivers is appended to the audit log as one line holding the canonical form of the decision record, and the append takes an exclusive flock around the write so that appends from parallel gates produce whole lines only. A decision whose append fails is not delivered, and the check command instead fails with a caller error naming the log failure, because an unaudited allow must not proceed. Reading the log verifies every line, and each line must parse as strict JSON and validate as a decision record under the field rules of obligation PC-4. The first line that fails is reported as corruption naming its line number, and a torn final line from a crash mid append is such a line and is never silently skipped. Naming a log file that does not stand is a caller error for the log command. This is covered by tests that append from parallel processes and read the log back, and that tear the last line and spoil a middle line and check the line each report names.

### Obligation PC-8 covers failing closed

When a policy cannot be loaded, for any reason from an unreadable file to an invalid rule, every call that passes schema validation is denied with the source named policy error and the load failure stated in the decision. The gate never decides without its rules and never applies part of an unloadable policy. A gate with no readable policy therefore denies everything put to it as a schema valid call, and the denial says why. This is covered by tests that present an unloadable policy in several shapes and check that each admitted shape of call is denied with the policy error source.

### Obligation PC-9 covers determinism and statelessness

Apart from the instant it is given, every field of a decision is a pure function of the policy document and the call document. The same policy and the same call always produce the same decision, the same source, the same reason, the same digest, and the same rewritten call. Rule order in the policy is the only ordering input. The gate keeps no state between calls apart from the audit log it appends to, and no decision depends on a decision that came before it. This is covered by tests that evaluate one call against one policy twice and compare the decision records field by field apart from the instant.

### Obligation PC-10 covers the honesty limits

The gate never executes a call, never intercepts a live call, and never touches the filesystem at a path a call names. It does not parse inner shell syntax, so the command string of an interpreter call is one opaque argument to matching, and a policy that allows an interpreter allows everything that interpreter can run. It does not resolve symlinks and does not stat targets, so a decision is a policy judgement about the call as written and not a guarantee about the filesystem at the moment the call runs. It judges no credential question, and a call naming a credential file is decided by the same rules as any other file call. This is covered by inspection of the package for any execution or interception or filesystem access against a call target, and by the interpreter tests under obligation PC-5.

### Obligation PC-11 covers the command line

The package runs as python -m portcullis and offers two commands. The check command takes a policy path, a log path, and one call document from a file argument or from standard input when no file is named. It prints the decision record as one canonical JSON line on standard output. It exits 0 when the decision is allow or rewrite, 1 when the decision is deny from any source, and 2 on a caller error, which is bad arguments, a call document that cannot be read or does not parse, or an audit log that cannot be appended to. Errors print as one line on standard error. The log command takes a log path and prints every verified record as one canonical JSON line each, exiting 0 when every line verifies, 1 when corruption is found with the report naming the line, and 2 on a caller error such as a log file that does not stand. This is covered by tests that drive the command line for every decision outcome and every caller error shape and check the exit code and the printed record each time.

### Obligation PC-12 covers the limits of slice 1

Slice 1 wires the gate into no harness, intercepts no live call stream, and executes nothing. It makes no model calls, and the decision record carries no model fields. It distributes no policy, reads no remote policy, and knows no per user profiles, only one local policy file. It limits no rate and remembers no call. It matches no second path of a move call, as obligation PC-6 states. Anything beyond these limits is a later slice and is not claimed here.

### Repair note for Round 1 slice 1

This note records the repair pass that followed the three reviews and the advisory review of the first build of this slice. The interpreter marker now follows the rule stated in obligation PC-5 for rewritten calls as well as proposed calls. The audit log reader now validates a rewritten call against obligation PC-1 and checks the agreement among the decision and the source and the reason and the interpreter flag and the digest form that obligation PC-4 implies. The policy and call readers now treat text that does not decode as the failures their obligations already name, and the log reader decodes each line on its own so a line that does not decode is corruption at that line. Argument conditions in a policy now refuse a missing index or a missing match as a policy error at load. A document whose strings are not encodable text does not parse, for this gate and its purposes, and that ruling is applied inside the strict parser so the call shape lands on the caller error seam and the policy shape lands on the load failure seam. The wording of obligations PC-1 and PC-2 now states the not empty checks the code already enforced for the network method and the network host and the rule id, and four refusal messages now name a value of no use where the empty shape and the wrong type shape share one refusal.
